TPG CMS CLI

A command-line tool for TPG's editorial team — connecting Claude directly to the Sanity CMS for content auditing, AI-assisted enrichment, and first-draft scaffolding. Built on sanity exec + the Anthropic SDK.

npm install -g @tpg/cms-cli
Available commands
$ tpg cms audit
Surfaces all articles flagged as stale, expired, or requiring review. Sorted by priority score.
Sanity GROQ ↔ Dashboard
▶ Click to run
$ tpg cms enrich --article "chase-sapphire-preferred"
AI-fills missing or stale metadata fields on a specific article. Dry run by default — use --write to commit.
Claude Sanity patch
▶ Click to run
$ tpg cms draft --card "amex-platinum-2026"
Scaffolds a first-draft article from the Sanity card catalog. Creates an unpublished draft — writer owns voice and judgment.
Claude Sanity draft
▶ Click to run
$ tpg cms freshness-check --days 90
Scores all 847 articles against the freshness threshold. Outputs a prioritized report and saves JSON to disk.
Sanity GROQ
▶ Click to run
↔ Connected to Content Health Dashboard
tpg cms audit runs the same GROQ query powering the Content Health Dashboard — giving editors the same data in their terminal. Writers who prefer a UI see it there; engineers who prefer a terminal see it here. One data source, two surfaces.

Safety model
All commands are dry-run by default
Use --write to commit Sanity patches
Schema validation on every AI-generated output
Full audit log written to ~/.tpg/audit.log
Design decision: This is deliberately a CLI, not a UI. Power users (editors who live in their terminal, engineers running batch jobs) get a tool that fits their workflow without adding another browser tab. The CLI and the Sanity Content Health Dashboard share the same data source — same GROQ query, same staleness scores. One data layer, two surfaces for two different user types.
